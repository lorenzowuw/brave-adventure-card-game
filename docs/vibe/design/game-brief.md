# 《勇者大冒险》Game Brief

> 基于 `game_design_plan.md` v4.0 收敛。
> 本文档只定义可执行方向，不锁死最终数值。

## 一句话定位

在原创奇幻大陆中，玩家选择一名火柴人冒险者，通过回合制卡牌战斗、树形地图选择、局内卡组构筑与角色成长，挑战区域 Boss 并逐步解锁更多角色与祝福。

## 目标平台

- 优先：Web/H5
- 当前技术栈：React + TypeScript + Vite
- 存档：localStorage
- 资产策略：代码绘制优先，AI 生成只用于风格稿、关键角色/背景/图标

## 目标玩家

- 喜欢卡牌构筑、轻量 roguelike、RPG 成长的玩家
- 需要低理解成本：颜色稀有度、敌人意图、角色定位标签、有限地图预览

## 核心体验关键词

- 轻松明快的奇幻冒险
- 火柴人动作表现
- 卡组越剪越强
- 角色越解越多
- 每局路线和奖励不同

## 30 秒核心循环

选一个地图节点 → 进入战斗/事件/商店/休息 → 打牌或做选择 → 获得卡牌/金币/经验/祝福 → 回到地图继续选择。

## 3 分钟核心循环

完成数个节点，逐步强化卡组和角色等级，看到下一层有限预览，在风险、商店、休息、精英战之间做路径选择，最终面对当前区域 Boss。

## 长线循环

击败 Boss → 解锁新角色、新区域、新祝福池和更高全局等级 → 用新角色和新机制重开下一局 → 收集图鉴和成就。

## MVP 范围控制

### Must

- 角色选择：至少 3 个初始角色可选。
- 战斗循环：抽牌、能量、出牌、护甲、伤害、敌人意图、结束回合。
- 卡牌系统：至少攻击/防御/回复 3 类卡，支持费用和稀有度颜色。
- 敌人系统：至少普通怪 + Boss，各有意图循环。
- 地图系统：树形地图，当前层可选，下一层有限预览。
- 奖励系统：战斗胜利后可选卡牌/金币/经验。
- 休息/商店/事件：至少各 1 种可交互节点。
- 局内成长：经验升级影响 HP/能量，至少能升到 Lv3。
- 全局进度：localStorage 保存已解锁角色和胜场。
- 火柴人视觉：至少能用代码或简易素材显示玩家、敌人、卡牌。

### Nice

- 6 个初始角色完整实现。
- 卡牌升级链：Lv1 → Lv2 → Lv3。
- 技能祭坛、焚卡炉、删卡服务。
- 祝福三选一。
- 精英战、奖励关、训练场。
- 5 个区域主题。
- 元素共鸣图鉴。
- 风险系统。
- 简单音效和 BGM。

### Out of Scope（MVP 不做）

- PvP。
- 创意工坊/Mod 编辑器。
- 多语言。
- 复杂剧情分支。
- 大量 AI 插画资产。
- 全角色全 Boss 全区域一次性做完。
- 真实人物或版权角色参考。

## 首个可玩目标

玩家能选择 1 名角色，在 1 张树形地图中经历至少 3 个节点，完成 2 场普通战斗和 1 场 Boss 战，胜利后记录一次通关进度。

## 技术复杂度判断

| 模块 | 复杂度 | 数据承载 | MVP 策略 |
|---|---:|---|---|
| 战斗状态机 | 高 | TypeScript 系统 + JSON 卡牌/敌人 | 先做单敌人战斗，不做多敌人 |
| 卡牌效果 | 高 | `skills.json` + 效果解释器 | 先支持 damage/heal/armor/draw/energy |
| 地图路线 | 中 | `maps.json` | 固定树形图数据，不先做程序化地图生成 |
| 角色成长 | 中 | `characters.json` + `level_up.csv/constants` | Lv1-Lv3 先跑通 |
| 全局解锁 | 中 | localStorage | 只存 unlockedCharacters/totalVictories |
| 商店/事件/休息 | 中 | JSON 配置 | 每类先做 1-3 条内容 |
| 美术表现 | 中 | CSS/Canvas/SVG + 少量 PNG | 代码绘制为主，AI 只出风格参考 |
| 音频 | 低 | assets/audio | MVP 可无声或 CC0 音效 |

## 市场支撑

- 相关赛道：卡牌构筑 roguelike + 轻 RPG 成长。
- 近期验证信号：未接入外部市场快照；当前仅基于项目设计方案判断。
- 核心差异化假设：用火柴人 AI-Native 低成本资产策略，降低内容生产门槛；用 Boss 解锁角色和卡牌升级链增强长期目标。
- 风险假设清单：
  - 若火柴人视觉无法支撑角色识别，则角色收集驱动力会下降。
  - 若卡牌效果解释器扩展成本过高，则后续内容扩充会变慢。
  - 若地图分支选择缺少足够差异，则 roguelike 重玩价值会不足。

## 本次假设

- 继续沿用当前 React + TypeScript + Vite，而不是切换 Phaser/Godot。
- MVP 以现有代码为基础补齐工作文档，不立即重构代码。
- P0/P1 只做单人单敌人，不做队伍制多角色同场战斗。
