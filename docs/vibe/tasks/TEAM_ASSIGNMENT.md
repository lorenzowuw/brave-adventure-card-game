# 双人任务分工

> 默认使用“成员 A / 成员 B”占位。拿到真实姓名后可整体替换。
>
> 分工原则：
> - **成员 A**：核心系统、战斗、状态机、存档、数据一致性。
> - **成员 B**：UI、地图/节点体验、内容配置、美术接入、测试验收。
> - 任何跨边界任务，先由主责人完成最小闭环，再由协作人接 UI/内容/验收。

## 角色定义

| 成员 | 主责 | 不主责 |
|---|---|---|
| 成员 A | 战斗系统、RunState、奖励结算、存档、解锁、升级链、风险/共鸣底层 | 大量 UI 样式、资产生成 |
| 成员 B | React 组件、地图体验、商店/事件/休息 UI、内容配置、美术资产、手动测试/E2E | 战斗核心状态机重构 |

## 协作规则

1. 同一时间不要同时改同一个文件。
2. 成员 A 优先改 `src/systems/*`, `src/types/game.ts`, `src/data` 中 schema 相关。
3. 成员 B 优先改 `src/components/*`, `src/styles.css`, `src/data` 中内容填充。
4. 若任务需要同时改系统和 UI：
   - A 先实现系统函数和状态字段。
   - B 再接 UI 展示和按钮。
5. 每个阶段结束前共同跑 `npm run build`。
6. 每个功能至少有一条手动验收步骤写入对应阶段文档或 PR 描述。
